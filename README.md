# 观量 · Stock Monitor

本机独立运行的沪深 A 股分钟量规则监控客户端。Mac / Windows 共用界面及规则核心，无需自建服务器。支持行情提醒与本机模拟交易，不连接券商、不读取真实持仓、不提交实盘委托。当前版本为 0.6.60。

## 使用

1. 打开 Mac 应用“观量”。首次启动自动建立独立数据目录，导入12只自选及已核对历史缓存。
2. 输入六位股票代码添加自选，左侧选择股票查看分时量或日K；切换日期查看缓存。
3. “历史回放”使用已验证的历史涨停价/样本计算结果，只保存回放记录，不发送通知。新下载分钟数据如缺少认证历史涨停价，回放明确阻止，不猜测特殊股票涨跌幅。
4. 交易时段自动轮询行情，每轮完成后等待8秒，4只并发；实际采样间隔还包括请求耗时。启动时也会刷新一次行情；日K由独立任务检查本地缓存，15:15后按需增量补取已收盘日，不再每5分钟抓取一年。报价刷新不会重新下载日K。行情超过30秒视为过期；分钟数据超时、缺口或获取失败暂停相应判断。
5. “设置与通知”中点击“授权并测试本机通知”。可选择登录电脑后自动启动，默认不注册登录启动。
6. 关闭窗口后保留托盘/菜单栏监控；完全退出请使用托盘菜单“退出并停止监控”。电脑必须开机、联网且不休眠。
7. 数据管理按范围下载。分钟接口仅覆盖最近数日，无法取得的日期保持未知覆盖。日线按年度拆分请求；未复权，日成交量统一为股并以万股显示；保留原始来源单位。分钟量统一为股，分时图表换算为手。
8. “备份本地数据库”在数据目录生成一致性 SQLite 备份。恢复时先完全退出，保留原库副本，再用备份替换 monitor.sqlite3；不要在程序运行时替换或保留旧 WAL/SHM 配对文件。自动恢复向导尚未实现。

Mac 数据目录：`~/Library/Application Support/com.xreddot.stockmonitor/`。Windows 使用 Tauri 应用数据目录，界面“数据管理”显示实际路径。开发核心可用 `STOCK_MONITOR_DATA` 指定独立测试目录。

## 使用变化

### 大盘广度 / 阿姆氏 TRIN（2026-10-28，本地开发）

“大盘广度”显示每日 TRIN 曲线、上涨家数占比及上涨股成交量或成交额占比柱状图。按新浪沪深股票列表统计（含科创板），不使用自选股样本，不包含北交所、B 股与基金；部分存托凭证可能不在新浪列表中。按用户确认，先显示完整核验日期，之后在应用运行时每日积累，不回填无法核实的历史。作者视频两张截图的 10 个日期中，独立成交额口径均比成交股数口径更接近作者数值，因此默认成交额供对照，也可切换成交股数；作者股票范围、具体算法和采样时间仍未确认，两种均不声称等于作者口径。详情见 `docs/trin-author-table-comparison-20261029/`。

均线宽度使用截至 2026-10-28 的历史基准及后续连续完整收盘快照；随程序提供 10 月 29 日 16:02 采集、校验过的腾讯单来源收盘参照，日期、摘要或完整性不符时不会使用，也不会写入用户数据库。同日已有完整缓存优先；缺失其他日期时仍中断计算，不伪造连续数据。盘中只显示连续前一交易日的收盘参考，不是盘中均线宽度。

“市场观察”可手动记录当前页面的趋势阶段，配合所选日期的市场宽度与量能结构观察；它不自动判断趋势或输出买卖点。视频图中的红柱是作者的“评分”，计算方法尚未公开，页面红柱使用可核实的上涨组成交量或成交额占比，不能冒充该评分。PCR、股债利差、作者评分和作者 MCL 的口径也尚未确认。

指数、股债和期权收盘参考的后台检查会在交易日 16:30 数据进入采集范围时唤醒；其他时间每小时检查，失败后保留已有有效数据。唤醒不是数据源保证，网络、数据发布、系统睡眠或应用退出会影响实际更新。

页面另展示独立计算的标准麦克莱伦振荡值：以每日上涨家数减下跌家数分别进行 0.10、0.05 指数平滑后相减，以首个有效值初始化；需要至少 39 个交易日的同来源、同范围完整收盘数据。缺少已核对交易日历、缺失交易日、无效数据或切换来源时重置；初始化会影响数值。这是标准公式的研究值，**尚未证明与作者 MCL 一致**。所选日期达不到要求时显示“—”。

“股债估值参考”按 `100 / 上交所股票平均市盈率 - 十年期国债收益率` 显示百分点数，仅使用两项同日期均有值的数据。股票范围是上交所股票（含主板 A、B 股和科创板），国债取中国货币网 11:30 报价曲线均值；两项时点不同，不能表示全 A，也不能推断实际资金流向。作者的准确计算与轨道窗口未核实，因此不视为作者公式或信号。页面显示数据来源与补采时间，缺失交易日不连线；应用运行时在北京时间 16:30 后独立采集，失败保留有效历史。

“上证指数技术参考”使用腾讯的上证指数已结束日线；仅使用交易日历可核对、同一周所有交易日均存在的日线合成周线，不将未结束周当作完整周。布林带采用最近 20 根收盘价的简单均值及两倍总体标准差，CCI(14) 使用典型价格和平均绝对偏差；缺失交易日后分别重新累计 20、14 根，分母为零时不显示 CCI。作者视频画面可见 BOLL(20) 与 CCI(14)，但准确公式及交易条件没有得到完整证据，页面不输出交易信号。后台只在收盘数据可用的保守时间（北京时间 16:30）后独立更新，不影响自选监控；仅从已有年度交易日历覆盖的年初开始加载，未覆盖日期不推断。

“ETF 期权 PCR”使用[上交所每日统计](https://www.sse.com.cn/assortment/options/date/)中上证50ETF华夏（510050）或沪深300ETF华泰柏瑞（510300）的认沽成交张数 ÷ 认购成交张数，可切换标的并展示同一所选交易日的两项底数及 PCR。可得连续 20 个交易日时，以简单平均和总体标准差计算中轨及上下两倍标准差通道；中途缺日则重新累计。每种数据仅覆盖对应一只上交所 ETF 的期权，**不是全市场 PCR，也未验证与视频口径一致**。交易日历可核验且北京时间 16:30 后才采集当日；后台通常每小时检查一次；交易所返回空列表时约每10分钟重试，其他异常仍按每小时重试，失败保留已有数据并提示。历史数据保留采集时间，不能当作已经验证的事前信号。两个标的 2026-09-09 至 2026-10-28 的 30 个交易日样本在本地核验，原始公开响应与月报核对位于 `docs/sse50-pcr-validation-20261028/`；执行 `.venv/bin/python -m scripts.verify_sse50_pcr` 可重新获取当前最近 30 个有日历的交易日，不操作用户数据库。此脚本只在数据覆盖包含 2026-09-22 时执行该日月报交叉核对。

期权区域同时并排显示两只 ETF 在所选同一日期各自相对 20 日通道的位置；一方无数据或通道未达到 20 个连续交易日时分别标明。日终汇总不能判断盘中是否曾穿轨，也不产生见底或买卖信号。2026-08-12 至 2026-10-28 的 50 个交易日样本包含历史补采，新增来源记录在 `docs/pcr-comparison-validation-20261029/`，可用 `.venv/bin/python -m scripts.backfill_pcr_research` 在隔离临时数据库中重新收集最近 50 个交易日。

TRIN =（上涨家数 × 下跌股票成交股数）÷（下跌家数 × 上涨股票成交股数），也等于“每只下跌股平均成交量 ÷ 每只上涨股平均成交量”。涨跌相对当日昨收，以整只股票的当日累计量分组，**不是主动买卖量拆分，也不是资金净流入**。平盘、停牌、零成交不进入 TRIN；上涨家数占比的分母包含有成交的平盘股。缺失股票不当成零；缺少上涨/下跌组时 TRIN 无定义。

低于1反映上涨组平均成交量相对较大，高于1反映下跌组平均成交量相对较大。低于0.7仅是观察参考，不是经A股回测确认的买点。极低值也可能对应短期过热。只有5%个股上涨、TRIN为0.3的例子中，上涨组成交量占上涨与下跌合计量也仅约14.9%；这能说明成交活跃度集中，不能推出权重股、机构进场或满仓买入。原视频未明确其股票范围、成交量单位及原始底表，其具体读数和事后行情结论未在本功能中认证。

腾讯逐股完整时间戳锚定交易日期；新浪全市场分页代码表要求数量完整、代码无重复。普通A股原始量按手换算股，保留手级取整精度；科创板原始量为股，并用成交额/日内高低价检查单位。盘中独立线程按约3分钟启动间隔检查，耗时过长时会延后，15:15后核对收盘；盘中采集跨越约数十秒，值会变动。断网、睡眠、完全退出会中断采集，缺失历史不补造。采集不改自选、正式触发规则、通知或模拟账本。

本次核验10月27日：新浪股票列表内5,223只全部覆盖，576涨、4,600跌、40平、7只停牌/零成交；TRIN 0.379255，上涨家数占比11.04%。以新浪量价交叉核对5,216只有成交股票，价格/昨收一致，量差均不超过50股；重算 TRIN 0.379255125，与腾讯结果差约0.000000032。新浪只有时分秒，因此日期仍依赖腾讯时间戳，此比较不能独立认证新浪日期，也不代表未来盘中连续可用。后来与BaoStock同日快照交叉核对发现，新浪列表少一只中国存托凭证九号公司（689009）；对齐列表后，BaoStock结果0.379255125，与腾讯结果差约0.000000032。列表覆盖率不是对所有沪深证券种类的覆盖率。

复核命令（仅读公开行情，不打开用户数据库）：`.venv/bin/python scripts/verify_market_breadth.py --output docs/trin-validation-20261028/final`。输出保留完整原始明细、统计及交叉核对。后端检查：`.venv/bin/python -m unittest tests.test_breadth tests.test_mcclellan_breadth -v`；界面检查：`npx playwright test tests/ui/breadth.spec.ts --workers=1`。本地只读预览：`http://127.0.0.1:1420/?panel=breadth`。

- 做T支持“先卖后买／先买后卖”方向切换，保存在本机；浮窗明确列出方向和买卖价格，按实际卖出金额计算印花税。先买后卖为基准价买入、悬停价卖出，先卖后买相反；不改变触发规则或发送委托。

- 日K关闭滚轮、手势和滑块缩放，保留固定窗口拖动浏览、方向键与双击查看分时。相邻日K高低价不重叠时标注跳空缺口，阴影随回补缩减，完全回补后移除；浮窗保留形成范围和回补日期，盘中缺口明确标为未收盘。

- 相对触发浮窗新增做T扣费试算：默认1000股、佣金万2，最低佣金暂按每笔5元（可改）；分别计算双边佣金、卖出印花税、双边过户费和可选滑点。股数、佣金及其他费用在图表上方费用参数中调整；浮窗只显示计算结果，隐藏基准提示栏，佣金含过户费时可避免重复计算。仅按标记价卖出、悬停价买回的等量价差估算；悬停早于基准时只比较价格，不作为可执行做T。

- 自选列表展示最新报价、相对昨收的涨跌额与涨跌幅、当日振幅（最高减最低后除以昨收）；字段缺失时显示“—”。隐藏“买点研究”菜单入口。

- 分时图默认选中最近一个已确认“触发”标记，以该标记所在分钟价格为基准；鼠标移动时浮窗显示相对涨跌幅。手动点击其他触发后固定基准，点击“恢复最近触发”回到自动选择；切换股票或日期后重新默认选择。

### 市场机会（未来 1–3 个交易日建仓研判，2026-11-08，版本 0.6.60）

左侧“市场机会”面板给出本机生成的“未来 1–3 个交易日建仓研判”（issue screen_version = 9）。2026-11-08 按用户“内容太多看不到重点”的反馈重排为**首屏聚焦**布局：首屏只回答“买什么、什么时候买、买多少、什么价卖/止损”；同日新增**炒作雷达**，用于识别“东方系列/羊字辈/AI硬件/光伏/冰雪经济”这类名称辈、生肖玄学与事件题材炒作。市场背景/剧本/数据覆盖全部收进折叠区。面板只读公开数据与本机已核验缓存，不连接券商、不写自选、不发通知；“研判/建仓清单”是本机公开阈值规则的输出，不是预测或收益承诺。所有数值带来源、采集日期与口径，缺失项显示“待取得/—”，不猜测、不补造；浏览器只读预览会明确标注“静态样本，非实时研判”。

首屏四块（自上而下）：

1. 定调 + 首选：一行定调条（定调、进攻/试错/防守、仓位、研判窗口、行情日期、数据更新状态），紧接一行 focus“首选 方向 · 股票：状态原因”。
2. 炒作雷达（2026-11-09 起置于建仓清单之上）：最多 5 条名称辈/生肖玄学/事件题材炒作，列＝主题(+类型)/阶段/今日信号/代表标的/结论；阶段含启动初期/发酵/加速·高潮/分歧/退潮，启动初期高亮；点击行展开详情（信号、股票买卖点、风险、观察条件、证据）。名称类固定提示“无基本面证据、退潮回撤大、只宜小仓短线”。
3. 建仓清单（首屏主体）：最多 6 条（每个方向取低吸候选，排名前 2 的方向另加龙头），列＝股票（代码）/方向·角色/现价·涨幅/状态/买点区间/追高上限/止损/止盈目标/建议仓位/观察窗口；状态由本批行情按 6 项 gate 实时重算；点击行切换到对应方向的详情。次要行显示状态原因与“方向条件”摘要。
4. 方向详情：紧凑标签切换 8 个方向，默认展开首选方向；顺序＝机会 → 买入时机（触发条件/失效条件/gate 状态）→ 重点股票（角色、现价、涨幅、成交额、连板、均线/20 日高低、买点、卖点）→ 逻辑与风险。

折叠区（默认收起，summary 带一行关键数字）：

- “市场背景”：三大指数均线与量能、全市场广度、行业/概念资金、人气、热点四张观测卡；
- “行动计划”：三套剧本（修复延续/高低切分化/补跌防守，高亮当前适用一套）、交易时间表、风险提示；
- “方向排名与数据覆盖”：完整方向表、warnings/coverage、未入选检索。

买卖点与仓位定义（本机规则，1–3 日短波段；价格四舍五入两位）：

- 买点 buy_low–buy_high：按“回踩低点/MA5 与昨收上限”计算；追高上限 chase＝昨收×1.03（龙头×1.07、中军×1.05），竞价/盘中高开超过该价位不追。
- 止损 stop：取“当日低点/MA10 中较低者”与“当日低点×0.93”的较高值再×0.98；强势股 MA10 过远时止损不深于当日低点下方 7%。
- 止盈目标 target1：近 20 日高点若落在（现价×1.02, 现价×1.15] 内则取该前高，否则取现价×1.08；target2＝max(target1×1.06, 现价×1.15)，目标不超现价 +15%。
- 移动止损 trail：MA5 高于 stop 时取 MA5，否则 MA10 高于 stop 时取 MA10，否则为空。
- 卖点 sell_note：接近 target1 分批减半；收盘跌破 trail（均线）或 stop（防守位）离场；持有 1–3 个交易日。
- 仓位 sizing：进攻 低吸候选 1–1.5 成/其他 1 成；试错 低吸候选 ≤1 成/其他 0.5–1 成；防守 ≤0.5 成（观察为主）。
- 以上价位、目标与仓位均为本机阈值参考，不保证达成，**不构成任何投资建议**。

盘中数据校验与操作提示（2026-11-09 盘中修复后新增）：

- 面板每 15 秒检查一次；研判本机每 30 分钟重新生成（收盘后仍按最近收盘数据）。建仓清单的“现价·涨幅”列只使用通过时间校验的当批报价，并标注“实时 HH:MM”；没有有效当批报价时显示研判时价格并标“研判时”，不猜价。

炒作雷达定义（本机规则，2026-11-08 新增）：

- 识别来源：近 5 日涨停池 `reason_type` 中的引号词（如“东方”）与“字辈/生肖/玄学/谐音/跨年”标记；涨停股名称中共同出现的 2 字片段（≥3 家）；当年/次年十二生肖及常见谐音（如羊→羊/阳/洋/扬）；72 小时新浪滚动新闻关键词（AI硬件/算力、光伏/新能源、冰雪经济、人形机器人、固态电池、低空经济、可控核聚变、创新药、稀土/资源、消费/跨年）及匹配的概念/行业资金。单一股票的标签不构成题材，必须有新闻或匹配的概念板块。
- 阶段：启动初期（近 2 日首次出现同题材 ≥2 家涨停；事件类可用“新闻 ≥2 条且概念内涨停 ≤1”）、发酵（涨停扩散且资金/新闻跟进）、加速/高潮（最高板 ≥4 或今日涨停 ≥6 等）、分歧（涨停回落或昨日涨停今日转弱）、退潮（近 5 日有热度、今日无涨停）。
- 结论：启动初期“可小仓试错（≤0.5 成）”、发酵“回踩低吸，不追高”、加速/分歧“只观察”、退潮“回避”；事件类没有标的时“先观察，等首批涨停或资金确认”。雷达股票不额外取日线，买点/止损/目标只用当日报价计算。

数据来源与口径（详见 docs/opportunity-v2-20261108/SOURCES.md 与契约 CONTRACT.md）：

## iPhone 锁屏提醒

先从官方渠道安装 [Bark](https://bark.day.app/)，启用通知，在桌面设置页只填写设备密钥，不填完整 URL。密钥保存到 macOS Keychain / Windows 凭据管理器，不写入SQLite，也不返回界面。点击测试按钮，随后在手机锁屏实际确认。

实现调用固定 HTTPS `https://api.day.app/push`，仅发送股票、日期、触发时间、三分钟量及规则原因。[官方接口](https://github.com/Finb/Bark/blob/master/docs/en-us/tutorial.md)。不上传完整自选池或缓存。默认关闭手机推送，启用后不补发此前积压事件。

推送记录 accepted 仅代表服务接受；没有手机送达回执。失败最多尝试3次，超3分钟过期。关注 iPhone 通知权限和专注模式。两台客户端同时运行暂不做跨设备去重。

## 规则

版本 `running_max_inclusive_v1`，分钟标签09:31–11:30、13:01–14:56。正分钟量 >= 截至当时最大量成为候选（含并列）；后两完整交易分钟分别严格小于候选量则确认。确认价格未涨停触发；仍涨停则等待随后首次观测到的低于涨停价格。日终失效，午休衔接，缺口阻断，未结束分钟不参与。

`core/validated_engine.py` 原样复制已核对验证器，仅供历史回归。`core/rules.py` 是流式核心，使用当时已知的分钟和价格；不使用未来全天最高价。腾讯分钟缺少分钟高低价，候选触板状态记录为未知；确认价低于涨停本身足以满足后续低于涨停观察条件。实时等开板使用时间戳新鲜的采样价格，不捏造逐笔成交或精确首次开板秒数。短暂开板可能漏采。

启动/恢复时完整重放当天前缀，历史事件标记 recovered，不实时推送；持续观察间隔超过45秒也进入恢复。事件以交易日+股票+候选分钟唯一去重，SQLite持久化。本机通知通过持久队列记录提交结果，重启不会重发已接受的事件；若恰在系统提交中断，结果标记未知，不擅自重复。历史回放、补取和实时事件分别记录。

## 开发与构建

需要 Node 22 LTS、Python 3.12、Rust stable。Windows 另需 Visual Studio C++ 构建工具和 WebView2；Mac 需 Xcode Command Line Tools。使用隔离虚拟环境安装 `requirements.txt`，`npm ci` 安装前端依赖。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/package_core.py
npm run desktop
```

Mac：`scripts/build-mac.sh`。Windows：PowerShell 执行 `scripts/build.ps1`。CI定义位于 `.github/workflows/build.yml`，以本项目为独立仓库根目录使用。推送会触发Mac与Windows构建，结果以GitHub Actions为准。

内置Python核心通过stdin/stdout JSON行协议通信，安装包自带Python运行时，无需用户安装Python，无监听网络端口。开发工具链 `.toolchain/` 仅存在项目目录，不更改全局Rust配置。

浏览器预览：`npm run dev`，仅允许读取明确标注的历史预览数据，不能监控或发送通知。UI测试：先启动预览，`npx playwright install chromium` 后执行 `npx playwright test`。
